# USB Tethering و کانال کنترل

## هدف

اینترنت کامپیوتر از گوشی بیاید، و کنترل گوشی هم‌زمان زنده بماند.

## مدل فیزیکی

یک کابل USB می‌تواند چند USB function را هم‌زمان advertise کند (composite gadget):

```
Phone USB gadget
├── rndis / ncm     → آداپتور شبکه در ویندوز (اینترنت)
├── adb             → platform-tools (اختیاری)
└── mtp / ptp       → فایل (به کنترل مربوط نیست)
```

رفتار OEM یکسان نیست:

| رفتار | نتیجه |
| --- | --- |
| Pixel و برخی AOSP: `rndis,adb` | ADB و تترینگ با هم می‌مانند |
| بسیاری از سامسونگ/شیائومی: با روشن کردن تترینگ فقط `rndis` | ADB قطع می‌شود |
| بعضی ROMها با Developer option «Disable USB audio / keep ADB» | متغیر |

بنابراین معماری **نباید** به زنده ماندن ADB وابسته باشد.

## Channel A — USB Tethering

- کاربر از Settings اندروید USB tethering را روشن می‌کند (یا از Quick Settings).
- ویندوز یک آداپتور Remote NDIS می‌بیند، DHCP می‌گیرد، default route می‌شود.
- **کد این پروژه هرگز:**
  - USB mode را عوض نمی‌کند
  - `svc usb setFunctions` صدا نمی‌زند
  - `adb usb` / `adb reboot` در مسیر اتصال نمی‌زند
  - driver RNDIS را disable نمی‌کند
  - MTP را toggle نمی‌کند

وضعیت تترینگ روی ویندوز از روی وجود آداپتور RNDIS + gateway `192.168.42.129` (یا معادل OEM) گزارش می‌شود. این «حد اطلاعات قابل دریافت» است، نه API رسمی اندروید روی PC.

## Channel B + D — Control و Data

Agent روی گوشی یک TCP server روی همهٔ interfaceها باز می‌کند:

- پورت کنترل: `17890`
- فقط از session pairشده فرمان می‌پذیرد
- Heartbeat روی همین کانال است

کلاینت ویندوز به ترتیب این endpointها را امتحان می‌کند:

1. Gateway آداپتور RNDIS فعال (معمولاً `192.168.42.129:17890`)
2. آخرین IP موفق ذخیره‌شده برای این `pairingId`
3. اگر ADB زنده بود: `adb forward tcp:17890 tcp:17890` و سپس `127.0.0.1:17890` — **بدون** تغییر USB function
4. شکست → `Reconnecting`، تترینگ دست نمی‌خورد

اگر ADB وسط کار بمیرد، مسیر 1 باید به کار ادامه دهد.

## Channel C — Screen

پورت `17891`، اتصال جدا، فریم باینری length-prefixed.

قطع استریم (کاربر Capture را روی گوشی رد کند، یا `FLAG_SECURE`) فقط کانال C را می‌بندد. کانال A و B می‌مانند.

## ترتیب روشن‌کردن توصیه‌شده

1. USB debugging را یک‌بار برای نصب Agent فعال کنید (بعداً اختیاری است).
2. Agent را نصب و باز کنید، Permissionهای لازم را بدهید، Pairing را شروع کنید.
3. USB tethering را روشن کنید.
4. Windows Client را باز کنید؛ باید گوشی را روی subnet تترینگ پیدا کند.
5. کنترل را استفاده کنید. اینترنت PC باید برقرار بماند.

اگر تترینگ را قبل از نصب بخواهید، APK را با روش دیگری نصب کنید؛ کنترل بعد از تترینگ روی TCP کار می‌کند.

## چیزهایی که عمداً انجام نمی‌دهیم

- تونل کردن اینترنت از ADB (`adb reverse` برای proxy) — با نقش تترینگ تداخل دارد.
- Wi-Fi hotspot به‌جای USB — خارج از هدف فعلی (می‌تواند fallback بعدی باشد، نه مسیر اصلی).
- خاموش کردن تترینگ برای «پایدار کردن ADB».
